# CheckStock

Небольшой веб-прототип складского учёта по тестовому заданию **«Где сейчас товар?»**.
Реализованы только задачи первого ТЗ: остатки, склады ФФ, перемещения, FBS/FBO и история операций.

**Стек:** Python 3.12, FastAPI, PostgreSQL 16, SQLAlchemy 2, Alembic, HTML/CSS/JavaScript.

## Запуск через Docker (основной способ)

Нужны установленные **Docker** и **Docker Compose**.

Из корня проекта выполните:

```bash
docker compose up --build -d
```

Откройте **http://localhost:8000**. API и его описание доступны по адресу **http://localhost:8000/docs**.

При первом запуске автоматически создаются таблицы PostgreSQL через Alembic и загружаются тестовые данные из ТЗ. Повторный запуск **не обнуляет** остатки.

Если порт 8000 занят, перед запуском задайте другой:

```bash
APP_PORT=8080 docker compose up --build -d
```

Команды для просмотра логов и остановки:

```bash
docker compose logs -f web
docker compose down
```

`docker compose down` сохраняет данные в томе PostgreSQL. Чтобы **полностью удалить** тестовые данные и начать сначала:

```bash
docker compose down -v
docker compose up --build -d
```

> Конфигурация Docker предназначена для локальной демонстрации, а не публичного доступа: в прототипе нет авторизации. Пароль PostgreSQL по умолчанию — демонстрационный; для иной среды задайте переменную `POSTGRES_PASSWORD`.

## Данные по умолчанию

Один магазин, два склада фулфилмента:

| Артикул | Товар | Север | Юг |
|---|---|---:|---:|
| SKU-101 | Органайзер | 10 | 6 |
| SKU-102 | Контейнер | 5 | 0 |
| SKU-103 | Корзина | 0 | 4 |

Изначально **25 шт. физически на ФФ**, резерв и товары в пути — по 0.

## Что можно проверить в интерфейсе

- **Обзор и остатки** — каждый SKU на каждом складе: физически, резерв FBS, доступно. Отдельная таблица показывает три направления товаров в пути.
- **Перемещения** — отправка между ФФ сразу уменьшает физический остаток на складе-отправителе и увеличивает «в пути». Приёмка перемещения увеличивает физический остаток получателя.
- **Отправки FBS/FBO** — резерв FBS блокирует доступное количество без изменения физического остатка; при отправке он списывается с ФФ и учитывается по пути к клиенту. Отмена резерва освобождает товар. FBO сразу вычитается с ФФ, учитывается в пути к маркетплейсу до приёмки.
- **Склады** — создать, переименовать, архивировать (кнопка «Архивировать» выполняет безопасное удаление без потери остатков и истории). Архивные склады и числящиеся за ними товары остаются видны.
- **История операций** — дата, операция, артикул, откуда, куда, количество. Все изменения отражаются в одной базе.

### Правила учёта

`Доступно = Физически на ФФ − Резерв FBS`.

Перемещение между ФФ, FBS после отправки и FBO до приёмки показываются **отдельно от физических остатков**, чтобы одна единица товара не считалась дважды.

Каждая операция выполняется в транзакции. В PostgreSQL строки остатков блокируются при изменении (`SELECT ... FOR UPDATE`), а уникальные ключи операции (`Idempotency-Key`) и проверки статусов не допускают повторного списания или повторной приёмки. При повторе того же запроса возвращается его прежний результат. Если ключ повторён с другими данными, сервер сообщает об ошибке.

Если на выбранном ФФ товара недостаточно, операция отклоняется — даже при достаточном **суммарном** остатке. Интерфейс сообщает, сколько доступно на других активных ФФ; **автоматического списания с другого склада нет**.

При удалении ФФ используется архивирование, а не физическое удаление записей. Так остаются остатки, ссылки на склад и история. Новые отправки или приход на архивный ФФ запрещены; ранее отправленное туда перемещение разрешается принять, чтобы не потерять товар в пути. Существующий резерв FBS можно отправить или отменить.

## Тесты

Для запуска тестов **без Docker** нужен Python 3.12+:

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell
# .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты создают **изолированную временную SQLite-базу в памяти** через FastAPI TestClient; рабочая конфигурация из Docker использует **PostgreSQL**. Тесты не изменяют данные PostgreSQL.

Покрыты: исходные остатки, приход, FBS (резерв/отмена/отправка), FBO (отправка/приёмка), перемещение/приёмка, нехватка на выбранном ФФ при наличии товара на другом, архивирование с остатком и товаром в пути, недопустимые операции, повторное подтверждение и повтор ключа с изменённым количеством.

## Сквозной сценарий для проверки и видео (3–5 минут)

1. Откройте **Обзор**: 25 шт. всего, исходные SKU по складам, резерв 0, в пути 0. Объясните формулу доступного остатка.
2. На **Север** добавьте приход 3 шт. `SKU-101`: физический остаток 10 → 13.
3. Создайте перемещение **4 шт. SKU-101 Север → Юг**: на Севере 9 шт., между ФФ в пути 4. Примите его: на Юге 6 → 10 шт., в пути 0.
4. На Севере зарезервируйте **2 шт. SKU-101 под FBS**: физически 9, доступно 7. Отправьте: физически 7, резерв 0, FBS в пути 2.
5. С Севера отправьте **3 шт. SKU-101 по FBO**: физически 4, FBO в пути 3. Подтвердите приёмку FBO: в пути 0, физический остаток на ФФ не увеличивается.
6. Проверьте **нехватку**: попытайтесь зарезервировать 5 шт. `SKU-101` на Севере при наличии 4. Интерфейс покажет отказ и наличие на другом ФФ.
7. Откройте **Склады**, архивируйте **Юг** (там остаётся 10 шт. SKU-101 и 4 шт. SKU-103). Убедитесь, что остатки и записи в **Истории** сохранились. Объясните, почему архивирование безопаснее физического удаления.
8. Для **повторного подтверждения** воспользуйтесь API `POST /api/transfers/{id}/receive` или автоматическими тестами: повторная приёмка возвращает статус `received`, остаток не меняется. Завершите объяснением транзакций, блокировки строк и ключа идемпотентности.

На запись видео с голосом и загрузку его рядом с репозиторием требуется отдельное действие со стороны кандидата. Сценарий выше соответствует требованию ТЗ о демонстрации и объяснении решений.

## Устройство проекта

```text
app/
  main.py            # FastAPI: HTML, dashboard API, маршруты операций
  database.py        # подключение к БД и сессии
  models.py          # товары, склады, остатки, перемещения, FBS/FBO, журнал
  schemas.py         # проверки входных данных
  service.py         # транзакционные складские операции и тестовый приход
  templates/         # HTML-интерфейс
  static/            # стили и JavaScript
alembic/              # начальная миграция схемы PostgreSQL
tests/                # тесты складских сценариев
Dockerfile
docker-compose.yml
requirements.txt
requirements-dev.txt
```

Все операции над остатками выполняются на сервере, а не в браузере. Статусы и история операций сохраняются в БД, поэтому обновление страницы не меняет результаты учёта. Для единственного магазина из тестового задания отдельная сущность магазина не нужна.
